# Резюме этапа 2 — интеграция базы данных

## Готово

- SQL-схема семи таблиц перенесена в `migrations/001_init.sql`; начальные роли `client`, `manager`, `admin` находятся в `migrations/002_seed_roles.sql`.
- Сохранены ограничения, связи, индексы, статусы заказов, `password_hash` и `order_items.count` из согласованной схемы.
- Go-пакет миграций встраивает SQL-файлы в приложение, ведёт таблицу `schema_migrations` с SHA-256 и временем применения.
- Все ожидающие миграции выполняются в одной транзакции. Ошибка при применении или записи журнала откатывает транзакцию. Повторный запуск пропускает миграции с совпадающей контрольной суммой; изменённая или неизвестная миграция вызывает ошибку.
- Приложение применяет миграции при старте. SQLite DSN включает внешние ключи на каждом соединении.
- Добавлены Go-проверки схемы, ролей, ограничений, внешних ключей, повторного запуска, checksum и полного отката при ошибке.
- Сохранена независимая проверка `tests/db_schema_test.py`.
- README описывает настройки, запуск, миграции, проверки, реализованное и незавершённое. `.env.example` сохраняет текущие переменные.
- Ошибки старта выводятся структурированным JSON-логгером `slog`.

## Проверки

В текущей ветке `feature/stage-2-migrations` выполнено:

```bash
go test -count=1 ./...
go vet ./...
python tests/db_schema_test.py
```

Все три проверки прошли. Также временный бинарный файл дважды запускался на одной чистой тестовой базе: оба раза `GET /health` вернул 200; журнал содержал ровно две миграции, а роли остались `admin`, `client`, `manager` без дубликатов.

`go test` и `go vet` запускались с временным `GOCACHE` внутри рабочей папки, так как стандартный системный каталог Go-кэша недоступен на запись в текущем окружении. `go build` завершился успешно, хотя Go вывел предупреждение о невозможности обновить stat cache в системном каталоге модулей.
