# Clothing Store API

Учебный REST API магазина одежды на Go и SQLite. Сейчас в проекте готовы базовая инфраструктура сервера, health-check и схема базы данных с автоматическим применением миграций. Бизнес-эндпоинты магазина пока не реализованы.

## Требования

- Go версии, указанной в `go.mod` (1.27.2 или новее).
- Python 3 нужен только для независимой проверки SQL-схемы.

## Запуск

Скопируйте `.env.example` в `.env` и при необходимости измените настройки:

```dotenv
APP_PORT=8080
DB_PATH=./data/clothing-store.db
LOG_LEVEL=info
```

Запустите сервер из корня репозитория:

```bash
go run ./cmd/app
```

При запуске приложение откроет SQLite, применит неприменённые миграции в порядке имён файлов и добавит начальные роли. Каталог для файла базы создаётся автоматически. После запуска можно проверить сервер:

```bash
curl http://localhost:8080/health
```

Ожидаемый ответ:

```json
{"status":"ok"}
```

## Миграции

SQL-файлы находятся в `migrations/` и встроены в бинарный файл Go. Таблица `schema_migrations` хранит имя, SHA-256 контрольную сумму и время применения каждой миграции. Уже применённая миграция не выполняется повторно; изменение её содержимого или отсутствие миграции, записанной в базе, приводит к ошибке запуска.

Таблица журнала и все ожидающие миграции применяются одной SQLite-транзакцией. При ошибке транзакция откатывается целиком. Внешние ключи включаются параметром SQLite DSN при создании каждого соединения.

Проверки проекта:

```bash
go test -count=1 ./...
go vet ./...
python tests/db_schema_test.py
```

Python-проверка использует стандартный модуль `sqlite3` и независима от Go-тестов.

## Реализовано

- HTTP-сервер на chi, структурированные JSON-логи через `slog`, graceful shutdown.
- Конфигурация через `.env` и переменные окружения.
- Подключение SQLite, автоматические миграции и начальные роли `client`, `manager`, `admin`.
- Health-check `GET /health`.
- Схема семи предметных таблиц: `products`, `photos`, `roles`, `users`, `cart`, `orders`, `order_items`.
- Денежные суммы в копейках, `password_hash`, количество товара в позиции заказа, ограничения, связи и индексы из SQL-миграций.

## Пока не реализовано

- CRUD и каталог товаров, загрузка и выдача фотографий.
- Управление ролями и пользователями, регистрация, аутентификация и авторизация.
- Корзина, создание заказов, позиции заказов и история заказов.
- Проверка прав клиентов, менеджеров и администраторов на бизнес-эндпоинтах.

## Основные настройки

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `APP_PORT` | `8080` | Порт HTTP-сервера |
| `DB_PATH` | `./data/clothing-store.db` | Путь к файлу SQLite |
| `LOG_LEVEL` | `info` | Уровень JSON-логирования: `debug`, `info`, `warn` или `error` |
