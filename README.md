# Clothing Store API

Учебный REST API магазина одежды на Go и SQLite. Реализованы каталог товаров и фотографии. Сервер пока предназначен только для локальной разработки: изменяющие эндпоинты ещё не защищены авторизацией и слушают только `127.0.0.1`.

## Требования и запуск

- Go версии из `go.mod` (1.27.2 или новее).
- Python нужен только для независимой проверки SQL-схемы.

Скопируйте `.env.example` в `.env`, при необходимости задайте пути и запустите из корня проекта:

```bash
go run ./cmd/app
```

По умолчанию сервер слушает `127.0.0.1:8080`. Проверка готовности: `GET http://127.0.0.1:8080/health`.

## Настройки

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `APP_PORT` | `8080` | Порт локального HTTP-сервера |
| `DB_PATH` | `./data/clothing-store.db` | Файл SQLite |
| `UPLOAD_DIR` | `./uploads` | Каталог файлов фотографий |
| `LOG_LEVEL` | `info` | Уровень JSON-логирования: `debug`, `info`, `warn`, `error` |

При старте автоматически применяются встроенные SQL-миграции. Файлы фотографий хранятся в `UPLOAD_DIR`; в SQLite остаются их метаданные.

## API каталога

### Товар

`POST /product` создаёт товар, `GET /product` возвращает страницу списка, `GET /product/{id}` получает товар, `PUT /product/{id}` полностью заменяет его поля кроме ID, `DELETE /product/{id}` удаляет товар, если он не используется историей заказов.

Формат тела для создания и полной замены:

```json
{
  "name": "Футболка",
  "type": "футболка",
  "gender": "унисекс",
  "size": "M",
  "color": "чёрный",
  "description": "Хлопковая футболка",
  "brand": "Example",
  "season": "лето",
  "price": 249900
}
```

Цена — целое число копеек. ID — UUID, создаваемый сервером. Обязательные поля: name, type, gender, size, color, brand, season; description может быть пустым; price не может быть отрицательным.

Список принимает `limit` (по умолчанию 20, максимум 100), `offset` (по умолчанию 0), точные фильтры `type`, `gender`, `size`, `color`, `brand`, `season` и `sort=price_asc|price_desc`. Сортировка стабильна при одинаковой цене. Неверные и повторяющиеся параметры возвращают `400`.

### Фотографии

`POST /photo` принимает `multipart/form-data` с ровно одним полем `product_id` и одним файлом в поле `file`. Поддерживаются JPEG и PNG размером не более 5 MiB и разрешением не более 25 мегапикселей. Имя файла и путь генерирует сервер. `GET /photo/{id}` возвращает содержимое изображения, `DELETE /photo/{id}` удаляет фотографию.

## Файлы и согласованность

Загрузка сначала записывается во временный файл, затем публикуется под случайным безопасным именем и связывается с записью SQLite. При ошибке вставки файл удаляется. При удалении файл сначала перемещается в служебную корзину, затем удаляется запись БД; при ошибке БД файл восстанавливается. При запуске приложение восстанавливает файлы, ещё указанные в БД, и очищает незарегистрированные временные/осиротевшие файлы. Для файловой системы и SQLite используется общий mutex внутри процесса.

## Реализовано

- HTTP-сервер на chi, JSON-логи через `slog`, graceful shutdown и health-check.
- SQLite, автоматические миграции, начальные роли и включённые внешние ключи.
- CRUD каталога, пагинация, точные фильтры и сортировка по цене.
- Загрузка, выдача и удаление JPEG/PNG-фотографий с проверкой формата и лимитов.
- Защита истории заказов от удаления товара и согласованное удаление файлов.

## Пока не реализовано

- Регистрация, аутентификация, авторизация и роли в HTTP middleware.
- Корзина, создание заказов и управление заказами.
- Публичное развёртывание и доступ к серверу из сети.

Пока отсутствует авторизация, не публикуйте сервер в общедоступной сети.
