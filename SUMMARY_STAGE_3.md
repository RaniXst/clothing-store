# SUMMARY_STAGE_3

## Результат

Этап 3 добавляет каталог товаров и фотографии, используя существующие таблицы `products` и `photos` без изменения миграций.

## Реализовано

- JSON API товаров: создание, список, чтение, полная замена и удаление.
- UUID генерируется приложением; `price` передаётся и хранится как целое количество копеек.
- Список: `limit` 20 по умолчанию (1–100), `offset` 0, точные фильтры `type`, `gender`, `size`, `color`, `brand`, `season`, сортировка `price_asc` или `price_desc`.
- Удаление товара блокируется, если на него ссылается `order_items`; фотографии товара удаляются каскадно вместе с товаром.
- Multipart API фотографий с полями `product_id` и `file`; принимаются JPEG/PNG до 5 MiB и до 25 мегапикселей.
- Файлы хранятся в `UPLOAD_DIR` (по умолчанию `./uploads`) под случайными серверными именами, метаданные — в SQLite.
- Временная запись, атомарное перемещение в карантин при удалении, откат/восстановление при ошибке БД и восстановление/очистка при старте.
- Сервис пока слушает только loopback; изменяющие маршруты не имеют авторизации и не предназначены для публикации.

## Ключевые файлы

- `internal/product/`: модель, валидация, SQL repository, service, HTTP handler и API-тесты.
- `internal/photo/`: модель, SQL repository, service, HTTP handler и API-тесты.
- `internal/storage/`: локальное файловое хранилище, восстановление и тесты.
- `internal/config/`: добавлена настройка `UPLOAD_DIR`.
- `cmd/app/main.go`: подключение сервисов и маршрутов, восстановление хранилища, loopback bind.
- `README.md`, `.env.example`, `go.mod`.

## Проверки

Запустить `go test -count=1 ./...`, `go vet ./...` и `python tests/db_schema_test.py`. Для ручной проверки использовать временные `DB_PATH`, `UPLOAD_DIR` и локальный порт. Проверить создание/список/получение/полную замену/удаление товара, фильтры и неверные параметры; multipart upload/GET/delete фото; запрет удаления товара с заказанной позицией; повторный запуск с той же БД.

## Ограничения и следующий этап

Авторизация, пользователи, корзина и заказы API не реализованы. Для следующего этапа необходимо добавить аутентификацию и проверки прав до открытия сервера для публичной сети. Миграции этапов 1–2 сохранены без изменений.
