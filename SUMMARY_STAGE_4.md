# SUMMARY_STAGE_4

## Реализовано

- Регистрация клиента, вход, выход и `/auth/me`.
- Argon2id-хеш паролей с индивидуальной случайной солью и закодированными параметрами; хеш пароля скрыт из JSON DTO.
- Серверные SQLite-сессии на 12 часов. Токен и CSRF-секрет генерируются через `crypto/rand`; хранятся только SHA-256-хеши.
- HttpOnly/SameSite=Strict cookies, Secure для прямого HTTPS и конфигурация `AUTH_COOKIE_SECURE` для TLS proxy; CSRF защита изменяющих маршрутов.
- Login limiter: 10 попыток с IP за 15 минут, одинаковый ответ 401 для неизвестного email и неверного пароля.
- CRUD пользователей и ролей с admin-only авторизацией, пагинацией пользователей, запретом удаления пользователя с заказами, защитой системных ролей и последнего администратора.
- Начальная учётка администратора создаётся отдельной интерактивной командой `go run ./cmd/app bootstrap-admin`; пароль не передаётся через argv и вводится без отображения.
- Маршруты записи каталога и фотографий защищены ролью admin; чтение каталога и фото публичное. Сервер остаётся привязан к loopback.

## Изменения схемы

Добавлена только `migrations/003_auth_sessions.sql`: таблица сессий с хешем токена, хешем CSRF, user_id, временем создания и истечения; внешние ключи каскадируют удаление сессий при удалении пользователя. Миграции 001/002 и существующие таблицы не менялись.

## Ограничения

- Корзина и API заказов не реализованы; правила менеджера для заказов остаются будущей работой.
- Rate limiter хранит состояния в памяти процесса и не является распределённым.
- Сброс пароля и подтверждение email не реализованы.
- Cookie Secure за TLS-терминирующим proxy нужно включить переменной `AUTH_COOKIE_SECURE=true`.
- Загрузка файлов этапа 3 рассчитана на один процесс приложения для одной папки uploads.

## Ручная проверка

1. Выполнить `go run ./cmd/app bootstrap-admin` в терминале, проверить скрытый ввод пароля и отказ при повторном создании admin.
2. Запустить приложение; зарегистрировать клиента и проверить cookies и `/auth/me`.
3. Войти неверным email и неверным паролем: оба ответа должны быть одинаковыми `401`; повторить попытки до `429`.
4. Проверить изменяющий запрос без CSRF (`403`) и с CSRF (`2xx`), затем logout и отказ старой сессии (`401`).
5. Проверить гостевое чтение каталога, запрет записи гостю и клиенту, разрешение записи admin.
6. Проверить user/role CRUD, пагинацию, запрет изменения системных ролей, удаление пользователя с заказами (`409`).
7. Запустить `go test -count=1 ./...`, `go vet ./...` и `python tests/db_schema_test.py`.
